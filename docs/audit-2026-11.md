# November 2026 audit: website

Scope: the Astro site at basketballvideoanalyzer.com. The desktop app has its own record in `docs/audit-2026-11.md` in the app repo, and the plans for both repos live in the app's `plans/`.

## 1. Summary

The site is a small English-only Astro site that explains and distributes a free desktop app. The audit found a wrong Mac download label, two URLs per page, a dead download fallback, stale claims ("all offline"), no FAQ, no privacy page and four stale docs. All of that shipped within a week. The home page ranks around position 22 for the head query, so the remaining work is waiting on Search Console data and on the owner recording a demo video. No open item needs a plan.

## 2. Shipped from the audit

- URLs and fallbacks: one URL per page with the trailing slash, a download fallback that links to the releases page, dead files and a 1.8 MB unused 3D model removed (#28). The Mac download is labelled Apple Silicon and files are classified by extension (#30). A Mac DMG is preferred over a zip and Intel downloads are counted (#39).
- Search and answer engines: honest descriptions, the app schema on the home page only, page dates (#34); the six guides listed in `llms.txt`, with a note that there was no Intel Mac build (#33); a home-page FAQ with system requirements and FAQPage JSON-LD (#35); a free-tools table with Kinovea and LongoMatch and links to Basketball Stats App (#36).
- Comparison and task pages: Hudl alternatives with dated prices (#40), Kinovea (#41), Hoopsalytics (#42), Once Sport Analyser (#43), and shot charts from game film (#44).
- Privacy: a privacy page, and Google Analytics running without cookies and denied by default (#37).
- Accessibility: in-page links keep the URL hash and keyboard focus, and smooth scroll applies only without reduced motion (#32).
- Docs: a real README, `CLAUDE.md`, four stale docs removed (#31). Dependency fixes (#29).
- Plans 001 and 002 are done; the app repo's plan folder covers the rest.

## 3. Open work

None with a plan. Every remaining item waits on data or on the owner (section 4).

## 4. Waiting on

- Translated pages (the app has 11 languages, the site has English only and no hreflang): waits for the Search Console country report. If Spanish, Greek, Lithuanian, Turkish, Serbian or Slovenian traffic shows up, translate one page and watch it for two weeks.
- Demo video: the `DEMO_VIDEO_ID` constant in `src/pages/index.astro` is empty and the player block stays hidden until it is set. The owner records the video; then set the ID. Before that, check home-to-download clicks in Search Console and GA to see whether visitors drop off.
- Testimonials slot: filled only when a coach offers a quote.
- Task and comparison page results: check Search Console on the seven original pages and the new ones, and run the answer-engine re-grade, before writing more pages. Plan 002's note on more task pages stays a direction, not a plan.
- Version, size and date in the download fallback are hardcoded. This only shows when the GitHub API is down.

## 5. Decide

- Consent banner: decided against. Google Analytics stays in denied-by-default mode and Vercel Analytics is cookieless, so page views, referrers and countries are still counted. GitHub release downloads give the real install count. If it needs to change, add the small banner the owner's other sites use.
- Per-deploy IndexNow ping (second half of plan 002): not built. The analytics hub already submits this site's sitemap every Monday with the key file in `public/`.

## 6. Won't do, and why

- Replace the React island with an Astro component (about 45 kB gzip per page for one button): real payoff, but the site has little traffic and the work is medium. Optional.
- Speculation rules and cross-document transitions: limited browser support, small site.
- Hero stage on scroll-driven animation: half the block cannot be converted.
- A `/changelog` page from GitHub release notes: no demand signal.
- A download count badge: counts are too small to show.
- Trial-style landing pages per audience: the app is free.
- Comparison pages built from memory: only from the competitor's own public pages, with a "checked on" date and links. Anything that cannot be confirmed is left out.
- Case study or sponsored demo: no users to write about.
